## 添加一条信息

1. 打开 [Pages CMS](https://app.pagescms.org)，用拥有本仓库权限的 GitHub 账号登录。
2. 首次使用时安装 Pages CMS 的 GitHub App，只选择 `WDSDSASDZX/ai-atlas` 仓库。
3. 打开 `ai-atlas` 的 `main` 分支，选择 **AI 信息**，点击新增。
4. 填写名称、简介、分类、链接、收录日期。标签、费用、自己的评价和详细笔记可选。
5. 关闭“草稿”并保存。GitHub Actions 构建和部署成功后，刷新网站即可看到。

第一次保存前，请先在仓库 Settings → Pages 中将 Source 设置为 **GitHub Actions**。

## 内容分类

- **模型**：模型系列、具体版本、能力与评测记录。
- **工具**：可以实际使用的应用、平台和服务。
- **开源项目**：GitHub 仓库、Agent 框架、开发库。
- **资讯**：发布动态、研究文章、官方博客或其他信息源。
- **想法 / 灵感**：独立的思考、创意、待验证的设想。
- **学习 / 实践笔记**：学习过程、实际体验、实验和复盘。

**收录日期**是你整理这条信息的日期；**事件日期**可选，用于记录真实发布日期。预置条目只是起始收藏，并不代表最新发布。

## 在首页和时间线上展示

- **事件日期**决定条目进入「AI 动态」的哪一天。没有事件日期的资料仍可在资料库找到。
- **站点主题**可以多选，供动态与资料库筛选。**发布或跟踪状态**、**开放方式**、**使用入口**和**最后核对日期**会显示在详情页。
- 勾选**推荐**并填好**为什么重要**，可把当期的重要事件放到首页。月度导读使用「月度导读」标签，和当期条目共用月份标签，例如 `2026-11-月度`。
- **相关条目**在后台按标题搜索并选择，网站会让有关系的公开条目互相链接。

## 添加版本动态

1. 先准备公开的项目档案，再新增一条版本记录。
2. 填写关联项目的文件名（不含 `.md`）、版本名称、事件日期和官方发布链接。添加 `release` 标签可用于筛选。
3. 简介写本次最重要的改动。正文记录新增、修复、兼容性变化和升级后可以怎么验证。引用官方性能数据时，附上测试硬件和负载。
4. 发布后，条目会出现在「版本动态」归档和项目档案里。日期优先采用官方发布日期，有时间戳时换算到北京时间。

## 草稿和推荐

“推荐”会把内容置于默认排序前列。“草稿”会让条目不出现在生成的网站、搜索和详情页中。

**当前仓库公开，草稿原文仍能在 GitHub 和提交历史里看到。请不要保存密钥、私人信息或不想公开的内容。**

## 写详细笔记

可以添加适合场景、实际体验、局限、相关链接、图片、表格和代码。媒体文件保存到 `public/media`。后台已配置 GitHub Pages 子路径。

## 自由记录历程和想法

打开一条信息后，下列栏目都可以按需填写；空栏目不会出现在网站上。

- **发展历程 / 时间线**：点击 Add an item，每件事填写日期、标题、说明和来源链接。前台自动按日期从新到旧展示，与收录日期分开。
- **想法 / 灵感 / 使用记录**：每次想到什么就加一条，可填类型（灵感、实践、踩坑、复盘等）、日期和内容。记录按后台排列顺序显示。
- **自定义属性**：自由填写属性名和内容，例如版本、作者、适用场景、评分。
- **优点 / 局限**：可以逐项添加自己的判断。
- **下一步 / 待办**：写下计划，在后台勾选完成后重新发布，网站显示完成进度。
- **相关资料**：给每个链接填写名称、网址和收藏理由。
- **自定义栏目**：任意增加标题和多行文字，例如提示词、方案对比、问题清单、项目规划。
- **自由长文**：适合图片、表格、代码和复杂排版。

所有列表都可增删。可拖动排序的列表会依后台顺序展示，条目内的发展历程按事件日期排序。栏目文字保留换行，富文本排版请使用自由长文。栏目文字也会参与资料库与动态的关键词搜索。

想写独立的想法或实践文章时，新建一条信息，将分类设为“想法 / 灵感”或“学习 / 实践笔记”；官网、费用等字段可以不填。当前状态也可自由填写，例如“待研究”“正在体验”“持续关注”。

更新后先保存正在编辑的内容，再重新打开后台的 main 分支，即可读取新表单。编辑发生在 Pages CMS，网站展示发布后的内容；网站上的待办是展示状态，完成操作在后台进行。

后台的 **AI 信息** 列表中有一条“自由编辑示例（可改成你的笔记）”草稿，可以直接打开看各个字段的填法，再改成自己的内容。它默认隐藏，不会出现在公开网站。

## 不使用后台也能更新

在 GitHub 的 `src/data/directory/` 下创建 Markdown 文件即可。可以复制 `examples/entry-template.md`；文件名建议使用英文小写和连字符。仓库 README 中有完整示例。

## 内容没有更新时

到仓库 **Actions** 查看最近一次构建；构建失败时，已上线的版本不会被新内容替换。通常检查日期格式、必填字段和链接即可。
