## 具体改动

- 新版人工审批引入共享通道、联系人与通知模板，兼容邮件和多种团队消息工具。旧 Human Input 节点可以按需迁移。
- 新增 OpenTelemetry 追踪导出，覆盖应用和 Agent；Langfuse v4 和云端当前接收端获得支持。开启后可在 Chatflow 中观察 Agent v2 的工具调用进度。
- 知识文档可在提取和索引前进行恶意文件扫描，管理员为知识库选择扫描器及失败策略。OpenAPI 新增可设作用域和有效期的个人令牌，GitHub 知识源支持树形选择。

## 审批和可观测性如何接上

一个人工审批流程至少涉及等待状态、通知传递、身份核对和续跑。配置消息渠道只能验证第一步送达，应用还需要用审批事件恢复到正确的工作流节点。追踪侧观察从父工作流到 LLM 和工具的 span，并通过运行 ID 找到暂停前后的记录。

## 部署与回归边界

新版审批有各环境的配置要求，旧 Human Input 节点按需迁移。文件扫描也由开关、扫描器与知识库的失败策略共同决定。验证时用可控的扫描器模拟拒绝或超时，再检查导入是否按策略入库，错误是否对运营人员可见。

## 影响与验证

自托管升级先保留数据库和环境变量备份，核对官方迁移步骤及 worker 版本。用一个审批流程验证从送达、身份确认到恢复，用两个知识库验证不同扫描策略，同时检查追踪端能否完整串起工具调用。
