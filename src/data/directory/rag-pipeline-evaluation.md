## 先准备答案和证据

选一组短问题，每条都事先标好对应文档、页码或表格单元格。加入精确编号、语义近似、跨两份文档、资料中没有答案、引用已撤回的文档、用户无权限访问六类样本。保存文档版本和授权快照，训练或调参样本与验证样本分开。

## 三层分别验收

| 层 | 核对什么 | 常见问题 |
| --- | --- | --- |
| 解析和切分 | 标题、表格结构、阅读顺序、文档与页码 ID | 数字串行、切分丢掉标题 |
| 检索和重排 | 原始候选、过滤后候选、重排位置 | 精确编号漏召回、权限作用域错 |
| 生成和引用 | 送入模型的上下文、答案、每条引用 | 引文支持不了结论、空结果时猜测 |

先只看解析输出。Docling 可将版面整理为结构化文档，仍需验证表格边界与阅读顺序。随后冻结切分、嵌入模型、top-k 和过滤条件，分别测试 BM25、向量，以及在候选层融合后的结果。BM25 对精确词和编号通常是可用的对照，向量适合试同义改写。两路的原始分值范围不同，使用固定的融合方法或重排器，并保存融合前结果，避免把评分差异误当召回差异。

## 用哪些指标

- **证据 Recall@k** 计算前 k 个候选覆盖了多少已标注证据。多文档题要看所需文档是否同时出现。
- **引用正确率**逐条检查引用能否支持旁边的陈述，以及能否定位到源文档页或表格。相关但没有支撑该结论的文档应计为错误。
- **空结果及权限**验证系统能说明缺少证据，并检查无权文档是否进入模型上下文和可见日志。把删除、权限变更和重建索引加入回归。
- **成本与延迟**分别记录解析耗时、检索和重排的 P95、首 token、总 token 以及每次问答的检索轮数。多步检索需单独对比单步基线。

## 怎么定位一次失败

如果文档转换时已丢失表格单元，先修解析；如果正确证据在候选中但未进 top-k，检查排名；如果证据进入上下文而引用仍偏，检查引用格式、提示和模型。记录每条链路的版本与输入，做到只改一个环节后复跑全部样本。
